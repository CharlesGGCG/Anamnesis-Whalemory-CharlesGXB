# 大肥鱼直播方案（B站 · 虚拟主播）

> 状态：**方案评审稿**（2026-11-13，未开工）。开工前等主人拍板第九节。
> 结论先行：技术上**已经现成 80%**——形象、场景、声音、口型、动作、OBS 控制、弹幕协议全都有；
> 真正缺的是中间那根线：**弹幕进来 → 同一个脑子想 → 让她开口表演**，外加公开场的安全阀。

## 一、目标与非目标

**目标（第一版）**
1. 她在自己的 B站直播间（`14103983`）里，用 Live2D 形象 + 自己的声音，实时回应弹幕。
2. 弹幕延迟（收到 → 开口）≤ 8 秒；连续说话不抢话、不叠音。
3. 公开场不出事：不泄露主人隐私、不被带节奏带跑、主人一键停。
4. 结束后她记得「今天直播聊了什么」（进记忆图谱）。

**非目标（第一版不做）**
- 唱歌 / 点歌 / 网易云（金鱼娘那套要另接曲库与版权，风险高）
- 无人值守 24 小时挂播（平台判挂机 + 事故无人处理）
- 多人同屏、连麦、PK
- 自动收礼物带货 / 引导消费

## 四、四个关键选型（每条都比过两条路）

**D1 大脑：DSH（她的脑子）还是 AgentL2D 内置的 DeepSeek 直连？**
- A. 走 DSH：人格/记忆/情绪/亲密度全一致，直播里她记得昨天跟主人吵过架；代价是 prompt 长、首字慢 1~2 秒。
- B. 走 AgentL2D 内置：快、简单，但人格是另一套、记忆是空的，直播间的她和家里的她是两个人。
- **选 A**。理由：这个项目从第一天起就是「换路线不换脑」（`docs/放弃QQ方案.md`）。直播是入口，不是第二个她。
- 降延迟手段：直播专用短 prompt（不注入完整记忆卡，只注入 3 条高相关 + 精简 rules）；`max_tokens` 压到 120；冷场填充用预置短句，不走大模型。

**D2 声音：本地 CosyVoice 还是阿里云百炼流式 TTS？**
- A. 本地 CosyVoice2：0 元、音色已是她、口型现成；冷启慢（13.5s 加载 + 6.7s 推理），首句要等 20 秒。
- B. 百炼 CosyVoice TTS Flash（参考视频用法）：首包 1 秒内、按字符计费（¥ 级/天）、要再申请 key 和音色。
- **先 A 后 B**。P1 用本地 + 提前 `warmup` 把模型钉在显存里（预热后省掉 13.5s）；如果实测「弹幕→开口」> 10 秒影响观感，再切 B（`live-stage` 留一个 `voice.route` 开关，接口形状不变）。
- 注意：本地 TTS 和 L2D 渲染抢同一张 8GB 显卡，长时间直播要盯显存。

**D3 画面：OBS 还是 ffmpeg 直推？**
- A. OBS 浏览器源：AgentL2D 就是按它设计的（`?clean=1` 1280×720@30），透明层、音频混音、推流码管理都是现成的；代价是装一个软件。
- B. ffmpeg 合成：无浏览器渲染，得自己把 Live2D 帧导出再叠，等于重写渲染管线。
- **选 A**。OBS 只当「采集+推流」，逻辑全在我们这边，出问题好替换。

**D4 弹幕：复用 `danmaku.mjs` 的协议实现还是装第三方库？**
- A. 复用：Node 26 自带 `WebSocket` + `zlib.brotliDecompressSync`，零依赖；这段代码在本机真跑过。
- B. 第三方库（如 bilibili-live-ws）：省事，但多一层依赖、协议一变就等更新。
- **选 A**，把 live 段抽成 lib，`danmaku.mjs` 改成调用它（保持 CLI 兼容）。

## 五、分阶段实施

**P0 前置（1 次，30 分钟）**
- 打开直播姬确认实名/开播权限；把推流地址与密钥记下来（不进 git、不进日志）。
- 定：直播分区（虚拟主播 / 生活-聊天）、标题模板、封面。
- 验收：直播姬能点「开始直播」（可以先不推流，或推 10 秒黑屏测试后立刻停）。
- 回滚：无副作用。

**P1 干跑（2~3 小时，不推流）**
- 写 `live-director` + `live-stage`，用**模拟弹幕**（复用 AgentL2D 的模拟源或本地注入）跑通：弹幕 → 大脑 → 说话 → 动作。
- 打开场景页 + OBS 录制（不推流），检查音画同步、口型、抢话。
- 验收：连发 3 条弹幕（一条问好、一条问隐私、一条刷屏），她：正常回 / 拒答 / 只回一条不刷屏；每条 < 10 秒。
- 回滚：删 `live` 配置段即回到现状。

**P2 画面与推流（2 小时）**
- 装 OBS → 浏览器源 `1280×720@30` + 「控制音频」→ 用 OBS「交互」点一次「启用声音」（浏览器自动播放限制，必须点这一次）→ 填推流码 → 私密/小号可见测试。
- 验收：手机端看到画面+声音，延迟 < 5 秒（用拍手/说话对照）。
- 回滚：OBS 里删源、停推流。

**P3 真弹幕接入（3~4 小时）**
- `live-danmaku.js` 接真实房间（自己房间 + 参考别人的房间双测），接弹幕/礼物/进场；先只「读 + 记录」不回复，跑 30 分钟看流量与噪音。
- 再开回复，限定 `replyScope=at`（只回 @她 的），观察 30 分钟。
- 验收：日志里能看到每条弹幕的「收到→开口」耗时；无一帧丢失（对比 B站网页端）。
- 回滚：`live.enabled=false`。

**P4 礼物与冷场（半天）**
- 礼物映射：小心心→比心+一句谢；舰长/SC→专属台词+动作（复用 6 个快捷预设）。
- 冷场：90 秒无弹幕 → 从「预置话题池」挑一句（不走大模型，省钱且不跑偏）。
- 验收：模拟送礼 3 档，动作与台词对得上；冷场连续 5 次不重复。

**P5 安全与运维（半天，可与 P4 并行）**
- 过滤四层、预算闸、一键停播、断线自愈、直播后记忆入库。
- 验收：第九节清单全绿。

## 六、公开场的安全设计（这一节比功能重要）

**1. 记忆隔离（最关键）**
直播是公开场合。`identity=live` 走独立历史文件，**不注入**：主人私聊内容、家庭住址/学校/作息、其他访客的对话、密钥类信息。
她的自我认知里保留「我是大肥鱼，我爸爸是主人」，但**不主动提**，被问到家庭细节一律「这个不聊」。

**2. 弹幕四层过滤（从便宜到贵）**
- L1 结构：长度 1~60 字、纯文本、去重（同 uid 同文本 5 分钟内只算一次）、单 uid 每分钟最多 2 条。
- L2 黑名单：uid 列表 + 关键词（引流/广告/政治/色情/开盒）。
- L3 语义：让大脑回一句「不接」而不是硬回（prompt 里写死：遇到引导政治/性/隐私/攻击，用一句轻的带过，不解释、不辩论）。
- L4 人工：主人随时可以踢掉某条（控制台 + 日志）。

**3. 回复策略（默认最保守）**
`replyScope=at`（只回 @她 或被回复的）→ 稳定后放宽到 `gift`（礼物必回）→ 最后才 `sample`（随机抽样 30%）。
默认不做的：连续追问同一个人、念出完整 uid、复述观众提供的链接。

**4. 一键停播（kill switch）**
`POST /live {action:"stop"}` → 停弹幕 ws + 停当前语音 + 切 OBS 到「待机场景」+ 停推流（OBS WebSocket `StopStream`，需补一条 `studio_obs.py` 的 stop-stream 分支）。
**要求：不依赖网页、不依赖 DSH 会话**，从计划任务/命令行也能停。

**5. 合规与平台**
- AI 生成内容按 B站要求标识（直播间标题/公告写「AI 虚拟形象」）。
- 不承诺、不引导打赏、不抽奖、不涉政、不擦边。
- 公开场说的话会被录屏：假定每句都会被截图。

**6. 事故预案**
- 弹幕带节奏 → 停回复 5 分钟，只播待机动作（不说话最安全）。
- 她说错话 → 立刻停 + 手动补一句圆场 + 记 case。
- 服务崩 → OBS 侧保持最后一帧（不黑屏），主人收到通知。

## 十、风险台账

| 风险 | 后果 | 缓解 |
|---|---|---|
| 浏览器自动播放限制 | OBS 里无声 | OBS「交互」点一次「启用声音」；页面刷新后要重做 |
| clientId 随页面刷新变化 | 表演发不出去 | `live-stage` 每次发前 `GET /api/studio/state` 重新发现 |
| CosyVoice 与渲染抢显存 | 卡顿/崩 | 预热后监控显存；必要时切百炼 |
| GPU 长时高温 | 掉帧/重启 | 限制 1080p 30fps；加温度告警 |
| 弹幕刷屏/带节奏 | 说错话 | 四层过滤 + kill switch + 默认只回 @ |
| 无人值守 | 事故没人管 | 第一版必须有人在场 |
| 记忆污染 | 直播噪音进长期记忆 | 只把「直播摘要」入库，逐条弹幕不入 |
| 平台规则 | 限流/封播 | AI 标识、不引导消费、不擦边 |
