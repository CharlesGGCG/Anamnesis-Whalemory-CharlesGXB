# Case：客厅三个问题（每天重置 / 认错人 / 说话没人应）

> 2026-11-14。用户反馈：客厅里 ① 每天都像重置对话 ② 她俩对彼此和主人认不准 ③ 主人说话没人应。

## 一、现象 → 根因（实机核对）

| 现象 | 根因 |
|---|---|
| 说话没人应 | 每角色每天只有 **15 条**额度（`loungeDaily` 按日重置）；当天小鲸鱼 15/15、小C 14/15，主人再说话时 `loungeLeft<=0` 直接跳过 |
| 每天都重置 | 消息本身没丢（`lounge.json` 跨天保留），但① 额度每天重置、② 群聊上下文只取最近 10 条、③ 每个角色只有自己的私聊历史与记忆卡，群聊内容没进各自记忆 |
| 认错人 | 客厅 prompt 只说「你和其它 AI、主人都在这里聊」，没有名单和关系；而且 `petChat` 会把**私聊历史**拼进 system，模型容易接着私聊话题/身份说话 |

## 二、修法

### 服务端（`whaleweb/server.mjs`）

- `LOUNGE_QUOTA` 15 → **40**
- **主人说话不计额度**：`ownerJustSpoke` 时跳过 `loungeLeft` 检查、不 `loungeBump`
- 主人说话时允许**两个人都应**（`maxSpeakers = LOUNGE_CHARS.length`）
- **兜底**：主人都开口了、两个人都沉默 → 强制一个用 `force: true` 再生成一次（必须回一句）
- prompt 重写：名单 + 关系（小鲸鱼是女儿叫爸爸、小C 是姐姐）+ 「群聊不是私聊、只代表自己、不要冒充主人」+
  把主人刚说的原话放在最后并要求「第一句必须直接接住」
- 上下文：从 10 条扩到 20 条，并带「昨天及以前」的摘要行（跨天不再像重置）
- 自动聊天间隔 60s → **300s**（减少自说自话、复读旧话题）

### 插件（`pet-chat` / `pet-api`）

- `/chat` 新增 `lounge: true`：客厅调用**不读写私聊历史**、不召回私聊图谱/vault、不写记忆卡，system 换成「客厅群聊」场景
- 目的：避免群聊提示词污染私聊记忆，也避免模型拿私聊上下文回答群聊

## 三、验证

```text
node --check server.mjs / pet-chat.js / pet-api.js 均通过
重启 WhalewebServer 后：主人发消息，小C 直接回「主人，汤我端上来了…」
quota 前后不变（24/26 → 24/26）→ 主人说话不扣额度
兜底逻辑：两人都沉默时会强制再生成一次
```

## 四、生效与残余

- `whaleweb` 侧（额度、prompt、兜底、间隔）**已部署**
- `pet-chat/pet-api` 的 lounge 模式要 **DSH 重启**才加载；重启前客厅仍会拼私聊历史
- 群聊内容进各自记忆卡：依赖 16:46 重启后的按角色维护，重启后聊几句等 10 分钟即可
